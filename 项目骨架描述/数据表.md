## 用户题目 UserProblem

| 字段 | 说明 |
| --- | --- |
| id | 唯一ID |
| user_id | 用户 |
| problem_id | 题目 |
| 刷题次数 | 统计 |
| 掌握等级 | 枚举，共有Lv0-Lv5六个等级，详见【配置表-学习状态标签配置】 |
| 上次刷题时间 last_practiced_at | 最近一次成功保存提交记录的时间 |
| 预计复刷时间 next_review_at | 由状态行为表计算；首页据此筛选到期复刷题 |
| 遗忘次数 forget_count | 本次回忆判定为“遗忘回忆”时加 1，用于复刷排序 |
| 当日升级日期 last_level_up_date | 用户本地自然日；用于限制同一题每日最多升级一次 |
| 版本号 version | 乐观锁版本，避免重复请求覆盖状态 |
| 是否斩杀 is_slashed | 用户主动确认“完全掌握、不再复刷”时为 `true` |
| 斩杀时间 slashed_at | 用户点击斩杀并确认的时间，可为空 |

约束：`(user_id, plan_id, problem_id)` 唯一。题目等级、复习时间与斩杀状态属于某一计划；新建或重置计划后，同题在新计划中从 Lv0 重新开始。一条 PracticeRecord 可以重复提交，但每条记录保存后都必须独立关联一次 AIAnalysis；同一题在同一计划的同一自然日最多提升一个等级，降级和下次复刷时间仍按每条提交记录计算。

## 斩杀计划 StudyPlan

| 字段 | 说明 |
| --- | --- |
| plan_id | 唯一 ID |
| user_id | 用户 |
| question_bank_id | 选择的题库 |
| plan_type | `by_days` / `by_daily_new_count` |
| target_days | 按天数规划时填写 |
| daily_new_count | 按每日新刷数量规划时填写 |
| estimated_daily_new_count | 创建时计算的预估值 |
| estimated_daily_review_count | 创建时计算的预估值 |
| estimated_finish_date | 创建时计算后展示；后续不动态预测 |
| status | `active` / `reset` / `covered` |
| created_at | 创建时间 |
| reset_at | 重置时间，可为空 |

规则：每个用户至多一个 `active` 计划；创建新计划时，旧计划改为 `covered`，新计划立即启用。重置计划时，当前计划标记为 `reset`，清空首页任务展示，用户可重新创建计划；历史 PracticeRecord 不删除。

## 经验沉淀 ExperienceLibrary

| 字段 | 说明 |
| --- | --- |
| user_id / plan_id | 用户与当前计划；二者唯一 |
| thinking_markdown | 思路 Markdown 文档；阅读态渲染为列表，点击后可直接编辑 |
| syntax_markdown | 语法 Markdown 文档；说明文字配合围栏代码块渲染 |
| last_refined_at | 最近一次成功 AI 整理时间；用于增量筛选提交总结 |
| last_refinement_log_id | 最近一次可撤销 AI 追加日志；手动编辑后失效 |

约束：经验库按 `(user_id, plan_id)` 隔离。AI 只读取当前计划、`last_refined_at` 之后的非空提交总结；自行判断思路与语法，返回 Markdown 并增量追加，不改写已有文档。用户点击文档进入编辑态，失焦、切换文档、点击 AI 追加或离页时自动保存；手动编辑会使最近一次撤销失效。

## 经验沉淀日志 ExperienceRefinementLog

| 字段 | 说明 |
| --- | --- |
| user_id / plan_id / library_id | 所属经验库 |
| before_snapshot | AI 追加前的两篇 Markdown 文档和整理时间，用于一键撤销 |
| source_record_ids | 本次参与整理的提交记录 |
| status / undone_at | `pending`（已生成待保存）、`active`、`discarded` 或 `undone`，及撤回/撤销时间 |
