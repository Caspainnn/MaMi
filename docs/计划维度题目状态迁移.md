# 计划维度题目状态迁移

从第四阶段起，`user_problems` 的状态唯一性由 `(userId, problemId)` 调整为 `(userId, planId, problemId)`。

这使新建计划或重置后重建的计划拥有独立的 Lv0、复刷时间、斩杀状态和题目进度；旧计划的状态与提交记录不删除。

## 部署与迁移顺序

1. 上传并部署 `managePlan`、`managePractice`、`getQuestionBank` 与 `migratePlanScopedStates`，均选择“云端安装依赖”。
2. 在 `migratePlanScopedStates` 测试面板先执行：

```json
{ "action": "inspect" }
```

3. 仅当返回 `ready: true` 且 `missingPlanIdCount: 0` 时，再执行：

```json
{ "action": "migrate", "confirm": "plan_scoped_state_v1" }
```

4. 确认旧索引 `user_problem_unique` 为 `dropped` 或 `absent`，且 `user_plan_problem_unique`、`plan_review_schedule` 为 `created` 或 `exists`。
5. 重新编译小程序，创建新计划后验证新计划题目均从 Lv0 开始，无旧复刷和旧提交记录。

## 安全说明

- 迁移只删除旧的数据库**索引**，不会删除任何 `user_problems`、`practice_records` 或计划数据。
- 若存在 `planId` 缺失的历史状态，迁移会停止，不会自行猜测这些状态属于哪个计划。
- 迁移完成后不应再次创建旧索引 `user_problem_unique`。
