# 云开发初始化（阶段 1）

本项目当前绑定的云开发环境 ID 为 `cloud1-d7gwckvr53001d8bc`。小程序启动时会调用 `login` 云函数检查登录状态；用户在首页主动确认昵称授权后，云函数才会在 `users` 集合创建或更新用户记录。

数据库集合和索引使用云端 `initDB` 云函数初始化，不需要在控制台逐个手工创建字段。CloudBase 是文档数据库，字段会在业务记录首次写入时自动形成。

## 在微信开发者工具中部署

1. 打开项目后，确认工具顶部显示的 AppID 与云开发环境可用。
2. 分别右键 `cloudfunctions/initDB`、`cloudfunctions/login`、`cloudfunctions/importQuestions`、`cloudfunctions/getQuestionBank`、`cloudfunctions/managePlan`、`cloudfunctions/managePractice`、`cloudfunctions/generateAIAnalysis`、`cloudfunctions/manageExperience`、`cloudfunctions/submitFeedback` 与 `cloudfunctions/migratePlanScopedStates`，选择“上传并部署：云端安装依赖”。
3. 打开云函数 `initDB` 的测试面板，使用空 JSON 参数 `{}` 执行一次。
4. 确认返回值中的 `success` 为 `true`。
5. 在模拟器或真机重新编译项目，进入首页并完成昵称授权；云开发控制台的 `users` 集合会出现或更新当前用户记录。

## 微信昵称授权登录

`login` 云函数采用两步流程：小程序启动时只检查是否已完成登录；首页底部授权弹窗由用户主动确认后，前端使用微信授权获得昵称，云函数再从可信上下文获取 OpenID 并创建或更新 `users` 记录。该流程不请求头像。

已有历史用户记录如果没有 `profileAuthorized: true`，会被识别为尚未完成昵称授权，并在进入首页时再次展示登录引导。修改后请重新部署 `cloudfunctions/login`。

`initDB` 不会删除已有集合、数据或索引；重复执行时只跳过已存在的资源。

## 初始化内容

`initDB` 会在云端创建全部已确认的集合与索引，并写入两条默认题库记录。集合和索引通过 CloudBase 管理 SDK 在云函数环境中创建，平台会自动注入临时凭证；不需要配置或保存固定腾讯云密钥。该函数只供开发期从开发者工具手动执行；小程序页面不会调用它。

## 导入完整题库

`cloudfunctions/importQuestions` 包含从两个 CSV 生成的 242 道题目数据：LeetCode Hot 100 100 道、代码随想录 142 道。导入函数会幂等写入 `problems` 与 `question_bank_problems`；重复执行会更新已有文档，不会产生重复关系。为适配测试面板的短等待窗口，函数以 50 道题为一批并发写入。

1. 右键 `cloudfunctions/importQuestions`，选择“上传并部署：云端安装依赖”。
2. 导入 LeetCode Hot 100：在测试面板传入 `{"bankCode":"leetcode-hot-100","start":0,"limit":100}`。
3. 导入代码随想录：在测试面板传入 `{"bankCode":"carl-algorithm","start":0,"limit":142}`。
4. 每次预期返回 `success: true`、`writtenProblems` 与 `relations` 等于本次导入数量。
5. 在云开发控制台确认 `problems` 和 `question_bank_problems` 均有 242 条记录。

题库页面已读取当前计划绑定题库的云端题目数据，并支持搜索、分类筛选与详情查看。

## 阶段 1 集合与索引

阶段 1 实际读写的集合仅为 `users`；初始化脚本会预创建后续阶段已确认的数据集合，以避免后续手工建表。

| 集合 | 用途 | 必要索引 |
| --- | --- | --- |
| `users` | 微信用户身份与累计学习数据 | `openid` 升序、唯一 |

推荐权限：将 `users` 配置为“仅创建者可读写”。阶段 1 所有创建和查询都由云函数处理，不需要开放客户端数据库权限。

## 后续阶段预留集合

阶段 2 开始前，依据 [数据表](../项目骨架描述/数据表.md) 创建以下集合：

`question_banks`、`problems`、`question_bank_problems`、`study_plans`、`plan_problems`、`user_problems`、`practice_records`、`ai_analyses`、`ai_usage`、`daily_situations`、`experience_libraries`、`experience_refinement_logs`、`user_feedback`。

`user_feedback` 用于保存“我的”页提交的产品建议，字段包括 `userId`、`category`、`content`、`status` 和创建时间。部署新版本 `initDB` 后执行一次 `{}` 即可增量创建，无需手动建字段。

若项目已在旧的“用户 + 题目”状态模型下运行，按 [计划维度题目状态迁移](计划维度题目状态迁移.md) 完成一次索引迁移后再创建新计划。

## AI 云函数配置

`generateAIAnalysis` 与 `manageExperience` 均需要在各自云函数详情中配置相同的 `MAMI_AI_API_KEY` 环境变量；密钥不得写入代码、测试参数或仓库文件。部署后请在“基础配置”中确认超时时间为 30 秒且公网访问开启。AI 总结与经验沉淀均仅在用户主动点击按钮时调用。

## 发布前静态检查

在项目根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\verify-phase4.ps1
```

脚本会检查全部云函数入口的 JavaScript 语法，并扫描仓库中是否误提交疑似 API Key。

题库导入、计划读写权限和业务记录写入将在对应阶段实现时接入。
