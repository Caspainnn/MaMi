# 问题与解决方案

用于沉淀开发中经过多轮排查才解决的问题。每条记录保持简洁，包含可复现现象、根因、修复方式和验证方法，避免同类问题重复排查。

## 2026-07-22：`initDB` 云函数初始化集合与索引失败

| 项目 | 内容 |
| --- | --- |
| 现象 | 首次执行提示集合已存在；修正后又提示 `createIndex is not a function`，随后提示 `EnvId is required`。 |
| 根因 | 当前 `wx-server-sdk` 可创建集合和写数据，但集合对象不支持索引管理；CloudBase 管理 SDK 在云函数测试环境中未能从调用上下文取得环境 ID。 |
| 解决方案 | 使用 `@cloudbase/manager-node` 管理集合与索引，使用 `wx-server-sdk` 写入默认数据；管理 SDK环境 ID依次读取调用上下文、运行环境变量和项目默认环境 ID。 |
| 复验方式 | 以“云端安装依赖”部署 `cloudfunctions/initDB`，在测试面板执行 `{}`；返回 `success: true`，并在云开发控制台确认集合、索引与默认题库记录。 |
| 预防措施 | 云函数中不要假定 `collection.createIndex` 可用；涉及集合/索引管理时优先使用管理 SDK。云函数测试面板的上下文信息可能不完整，需提供安全的环境 ID 兜底。 |

## 2026-07-22：`importQuestions` 在测试面板超时

| 项目 | 内容 |
| --- | --- |
| 现象 | 导入 242 道题目时，云函数测试面板返回 `Invoking task timed out after 3 seconds`。 |
| 根因 | 初版存在两层问题：大量写请求会导致测试面板超时；更关键的是 `doc.update()` 对不存在的固定 ID 文档可能返回影响 0 条而不抛错，函数误报“更新成功”，实际没有写入数据。 |
| 解决方案 | 诊断阶段先限制为 10 题；题目与关联均改用 `doc(id).set()`。稳定 ID 下，`set()` 会创建缺失文档、覆盖既有文档，重复运行不产生重复数据。 |
| 复验方式 | 重新部署 `importQuestions`，用 `{}` 运行；预期返回 `success: true`、`total: 10`、`writtenProblems: 10`，且 `verification.readableProblemsInSample`、`totalProblemsInThisEnv` 均为 10。 |

## 2026-07-22：242 道题库数据的云端导入与续传

| 项目 | 内容 |
| --- | --- |
| 现象 | 直接导入完整题库会触发云函数测试面板 3 秒超时；首次使用 `update()` 时还会出现返回“更新成功”、实际集合为空的假成功。 |
| 根因 | 测试面板调用窗口较短；`update()` 不适合用作“文档不存在则创建”的判断依据。 |
| 解决方案 | 使用稳定的题目/关联文档 ID，并改用 `doc(id).set()` 幂等写入。LeetCode Hot 100 采用一次 100 题导入，代码随想录采用 100 + 42 两次导入；每次均由函数回读抽样和总数校验。 |
| 验证结果 | `problems` 与 `question_bank_problems` 均为 242 条；其中 LeetCode Hot 100 为 100 条（原始 CSV 100 行、100 个唯一 `problem_id`），代码随想录为 142 条。 |
| 预防措施 | 导入函数应返回写入后的回读核验与总数；大批数据导入优先采用可重试、稳定 ID 的幂等写入，并根据平台调用时限分批执行。 |

## 2026-07-23：AI 云函数初始化与 3 秒超时

| 项目 | 内容 |
| --- | --- |
| 现象 | 初次调用报 `ai_usage` 集合不存在；集合创建后，日志仍显示 `Invoking task timed out after 3 seconds` 和 `Duration: 3000ms`。 |
| 根因 | AI 调用额度依赖新增的 `ai_usage` 集合，部署代码不会自动创建集合；普通云函数线上默认超时为 3 秒，外部 AI 接口未在此时间内返回，且云端实际超时配置未生效。 |
| 解决方案 | 部署最新版 `initDB` 并执行一次，确认 `ai_usage` 和其索引存在；部署 AI 函数时云端安装 `ws` 依赖；在云函数详情的基础配置中手动把超时时间设为 30 秒，并确认公网访问和环境变量 `MAMI_AI_API_KEY`。 |
| 复验方式 | 点击小程序“AI 总结”，应在超时时间内把结果填入总结框；日志不再出现 `Duration: 3000ms`。若仍失败，按新的 HTTP 状态码、DNS 或鉴权日志继续定位。 |
| 预防措施 | 新集合/索引必须由 `initDB` 创建；依赖外部服务的云函数发布后，必须核对云端实际超时和网络配置，不能只依据本地配置文件。 |

## 2026-07-23：同行轻量操作按钮的实现

| 项目 | 内容 |
| --- | --- |
| 现象 | 在信息标题同行放置轻量操作按钮时，原生 `button` 容易受到默认最小宽度、边距和伪元素影响，视觉尺寸难以与页面内其他小控件保持一致。 |
| 解决方案 | 纯前端轻量操作优先使用带 `bindtap` 的 `view` 实现；自行控制宽高、边框、圆角与对齐。仅提交、确认等语义明确的主操作保留 `button`。 |
| 验证方式 | 对比同行按钮的宽度、圆角、文字垂直居中与右对齐；确认点击事件正常触发。 |
